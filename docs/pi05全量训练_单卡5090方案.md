# π0.5 / π0.6 全量训练：单卡 5090 方案（2026-11-18，来自 FEM_sim 会话）

**目的：**不租 A100 80G（7.3 元/小时），用本机 RTX 5090 32 GB 加 125 GB 内存做**全量微调**（不用 LoRA）。
这份文档是方案和估算，**还没有实测**。第一步先做第 3 节的试跑。

## 1. 结论

- **可以用 5090 做。**换成 PyTorch 训练路径（`scripts/train_pytorch.py`），先试纯 bf16；放不下再用 DeepSpeed 把优化器放到内存。
- **不要用 5090 加 3090 一起训。**两张 3090 在另外两台机器上（`ssh x99`、`ssh win3090`，用法见 FEM_sim 的 `docs/训练机_*_使用说明.md`）。跨机器训练时每一步都要传约 6.6 GB 梯度，即使走 100 MB/s 的直连网线也要 1 分钟以上；两张卡显存一大一小，用 FSDP 切模型也划不来。
- **GPU 归属（用户 2026-11-18 说）：**开始训练 π0.6 时，用户会把本机当前的 GPU 任务停掉，由用户来停。当前任务是 T-Rex 后训练，预计 11-19 中午结束。本会话不要自己停别的任务，先确认 GPU 已经空出来。

## 2. 显存估算（π0.5 约 3.3B 参数 = PaliGemma 约 3B + action expert 约 0.3B；以实际 `numel` 为准）

| 方式 | 每个参数占多少字节 | 显存 | 内存 | 5090 能否跑 |
|---|---|---|---|---|
| openpi 官方 JAX 版全量训练 | fp32 权重 + 梯度 + Adam | 大于 70 GB（README 写明） | — | ✗ |
| **A：PyTorch 版，`pytorch_training_precision="bfloat16"`**（权重、梯度、Adam m/v 全是 bf16） | 约 8 → 约 26 GB，另加激活值 | 约 28～32 GB（batch 1～4，梯度检查点已默认打开） | 少 | 勉强能跑，**先试这个** |
| **B：PyTorch 版 + DeepSpeed ZeRO-2 优化器放到内存**（bf16 权重和梯度放 GPU；fp32 主权重和 Adam 放内存，用 CPU Adam 计算） | GPU 约 4，内存约 16 | 约 15～20 GB | **约 55～60 GB** | ✓ 稳妥，每次参数更新多花约 5～8 秒 |

本机 T-Rex 用方案 B 跑 3.84B 参数的模型：显存 19.4 GB，CPU Adam 每次更新约 8 秒。可以拿来参考。

## 3. 第一步：试跑（约 30 分钟，GPU 空出来以后再做）

1. 把 JAX 检查点转成 PyTorch：`examples/convert_jax_model_to_pytorch.py`。另外按 README 的"PyTorch Support"一节，把 `transformers_replace` 拷进 venv。
2. 用全量配置（例如 `pi05_g1_pick_apple`，或者 LIBERO 的全量配置），设 `pytorch_training_precision="bfloat16"`，batch 从 4 开始，跑 50～100 步。
3. 记下：显存峰值（`torch.cuda.max_memory_allocated`）、每步耗时、loss 走势。OOM 了就把 batch 降到 2 或 1 再试。
4. 判断：
   - 显存峰值低于约 30 GB，loss 正常下降 → 按方案 A 正式训练；
   - batch 1 也 OOM，或者 loss 不降、出现 NaN → 改用方案 B；
   - 方案 B 太慢，或者内存放不下 → 回到租 A100。

试跑的结果写进本项目的 `docs/DECISIONS.md`，并告诉用户。

## 4. 需要改的代码

- **`train_pytorch.py` 没有梯度累积**，必须加上。batch 只能开 1～4，要累积到有效 batch 32（和 LoRA 配置一致）。梯度累积步之间不调用 `optim.step()` 和 `zero_grad()`；loss 要除以累积步数。
- **用方案 B 时：**按 ZeRO-2 + `offload_optimizer: cpu` 接入 DeepSpeed，也可以用 Accelerate 包一层。T-Rex 项目（`/media/hzm/data24t/GitHub/T-Rex`，看它的 `docs/DECISIONS.md` 中 11-18 的几条）已经踩过这几个坑：
  1. DeepSpeed JIT 编译 `cpu_adam` 时找不到 `-lcurand`：把 pip 装的 `nvidia/curand/lib/libcurand.so.10` 软链接到 venv 的 lib 目录。
  2. DeepSpeed 0.15 ZeRO-2 offload 第一次更新参数时，会把整个 fp32 分区拷到 GPU 上再转 bf16，导致 OOM：在 CPU 上分块转换后再拷（T-Rex 打了本地补丁）。另外加上 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`。
  3. 训练循环没有用 `accelerator.accumulate()` 时，梯度累积实际不生效，每个小 batch 都更新一次参数。要手动设置同步标志。
- 纯 bf16 的 AdamW 有精度隐患：更新量太小时会被舍掉。长时间训练效果可能比官方 fp32 略差。要和官方或 RLinf 的数字严格对比，用方案 B 或 A100。

## 5. 资源规则（本机是共用的）

- 机器配置：i9-14900K、125 GB 内存、64 GB swap。Abaqus 仿真也在这台机器上跑（受 `fem/abq.sh` 限额管：Abaqus 内存合计不超过 70 GB，整机可用内存不低于 20 GB）。
- 方案 B 要占 55～60 GB 内存。开始前先运行 `free -g`，确认可用内存在 70 GB 以上，并告诉用户这段时间不能跑大的 Abaqus 作业。11-12 曾因内存耗尽，导致桌面会话被注销。
- 速度预期：比租 A100 80G 慢约 1.5～3 倍（5090 的 bf16 算力低于 A100，batch 又小，还有梯度检查点和 offload 的开销），但不花钱。训练要几天的话，先给用户算一下总时长，再和租卡比较。
